The data processing stage focused on preparing the movie dataset for reliable similarity-based recommendation. Since the system relies on multiple natural language processing techniques, consistent and well-structured data was required to ensure that all models could operate on the same underlying information.

Data cleaning

The dataset was inspected for missing or empty values in the description field. A filtering step was applied to remove such entries, as textual content is required by all similarity models used in the system. This validation confirmed that no rows contained missing or empty descriptions, indicating that the dataset was already clean and suitable for further processing.

While the dataset itself was not deduplicated during preprocessing, duplicate movie title were handled at the output stage to imporve the clarity of recommendations presented to the user.

Feature Engineering

After validating the dataset, the description column was selected as the primary input for all models. Other attributes were not used during feature extraction or similarity computation.

To enable machine learning models to operate on textual data, the movie descriptions were transformed into numerical representations using multiple feature engineering techniques. Semantic sentence embeddings and emotion probability distributions were used to represent each movie description in numerical form, capturing both contextual meaning and emotional characteristics of the text. In addition, TF-IDF representations were generated at runtime to capture keyword based relevance. Together, these representations allow the system to analyze the same text from different perspectives and combine the strengths of several models.

After feature engineering, consistency between the movie dataset and all numerical feature representations was verified by confirming matching dimensions. This ensured that similarity computations were applied to correctly aligned data.

Data alignment

To ensure

Duplicate movie titles were not removed during the data processing stage. Multiple entries with the same title can represent valid candidates during similarity computation and model evaluation. Instead, duplicate titles were handled at the output stage, where only the final ranked list presented to the user was deduplicated. This design choice preserves all candidate information during processing while improving clarity in the final recommendations.
